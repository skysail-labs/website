# Working on the Darknyx docs

This is the **Docusaurus 3.10** documentation site. Read this before changing
anything here — the build has a non-obvious propagation step, and getting it
wrong makes your changes *look* like they did nothing (they build fine but the
live/served site is stale).

## The one thing that bites everyone

The site people actually view is **not** built from here on the fly. It is
served as pre-built static HTML committed at **`apps/demo/public/docs/`** (the
Next.js demo app serves that folder at `/docs`). So after ANY change here you
must regenerate and copy the build over:

```bash
cd apps/docs
npm run build                 # runs emit-raw-markdown, then docusaurus build → apps/docs/build/
cp -r build/* ../demo/public/docs/    # <-- the step that's easy to forget
```

On Vercel this copy is automatic (see root `vercel.json` → `buildCommand`), so a
deploy regenerates `public/docs` for you. But if you only run `docusaurus build`
and stop, nothing the user sees will change. **If a change "isn't showing," it is
almost always this.**

Local preview (reflects source instantly, no copy needed):

```bash
cd apps/docs && npm start     # http://localhost:3010/docs  (prestart emits raw markdown)
```

## Where content comes from — `portal/` is the source of truth

Doc pages under `apps/docs/docs/**` are **generated**, not authored in place.
The source lives at the repo root **`portal/`**, and
`sync_and_format_docs.js` (repo root) copies `portal/ → apps/docs/docs/` while:

- converting ASCII/plaintext diagrams into `mermaid` code blocks (per-file
  rules in that script — this is the "meticulous design" that gets lost if you
  bypass it),
- quoting YAML `description:` values that contain colons,
- stripping `link` from `_category_.json` so sidebar categories collapse.

**To edit page content:** edit the file in `portal/`, then run
`node sync_and_format_docs.js` from the repo root, then build + propagate.

> ⚠️ `sync_and_format_docs.js` overwrites `apps/docs/docs/**` from `portal/`.
> If you edit `apps/docs/docs` directly and someone later runs the sync, your
> edit is lost unless you also made it in `portal/`. It only *copies/overwrites*
> — it never deletes — so a page removed from `apps/docs/docs` (and absent from
> `portal/`) stays removed. The script is **manual**; it is not wired into any
> build.

Filenames use a `NN-` order prefix (e.g. `01-overview.md`); the number is
stripped for the URL slug (`get-started/overview`). Sections are folders with a
`_category_.json`. `reference/**` and `reference-data/**` are excluded from the
build (see `exclude` in `docusaurus.config.ts`).

## Theme, styling, and config — edit here directly

These are **not** touched by the portal sync, so edit them in place:

- **`docusaurus.config.ts`** — navbar, footer, sidebar behavior, site metadata.
- **`src/css/custom.css`** — global styles and the `--nyx-*` design tokens
  (gold accent is `--nyx-accent` / `--ifm-color-primary`). Reuse tokens; both
  light and dark themes are styled via `[data-theme="light|dark"]` blocks.
- **`src/theme/**`** — swizzled components (see inventory below). These are all
  **wraps or additive layouts**, never ejects that copy Docusaurus internals, so
  admonitions/tables/mermaid keep rendering exactly as upstream. Keep it that
  way: prefer wrapping `@theme-original/...` over ejecting.

### Swizzled component inventory (`src/theme/`)

| Path | What it does |
| --- | --- |
| `DocItem/Content/` | Injects the `CopyPageMenu` above each page body |
| `CopyPageMenu/` | The "Copy page" dropdown (Copy/View Markdown, ChatGPT, Claude, Cursor, Copy MCP Server). Brand SVGs in `CopyPageMenu/brand/` are forced to `currentColor` for light/dark |
| `DocItem/TOC/Desktop/` | Adds the "On this page" heading + icon; sticky wrapper |
| `Footer/Layout/` | Brand-left / link-columns-right footer |

## Raw markdown + the MCP server

- `scripts/emit-raw-markdown.mjs` writes a plain-markdown copy of every page to
  `static/<slug>.md` (served at `/docs/<slug>.md`). It runs automatically via
  `prestart`/`prebuild`. Output is gitignored.
- The docs MCP server is a **separate** thing living in the demo app
  (`apps/demo/src/app/api/[transport]/route.ts`, public URL
  `https://darknyx.trade/api/mcp`). It reads `apps/demo/src/generated/docs-index.json`,
  regenerated by `apps/demo/scripts/build-docs-index.mjs` (part of the demo
  build). Removing/renaming a page updates that index on the next demo build —
  you don't edit the JSON by hand.

## Checklist for a docs change

1. Content? Edit `portal/` → `node sync_and_format_docs.js`. Styling/config? Edit
   `apps/docs/**` directly.
2. `cd apps/docs && npm run build`
3. `cp -r build/* ../demo/public/docs/`   (or just let Vercel deploy)
4. Verify: check `apps/demo/public/docs/<page>/index.html`, and preview at
   `localhost:3010/docs`. Confirm admonitions/tables/mermaid still render.
5. Do not commit unless asked; leave the commit to the maintainer.
